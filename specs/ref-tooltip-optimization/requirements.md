# 需求文档 - Ref引用悬浮卡片优化

## 介绍

当前的ref引用功能虽然有悬浮卡片界面，但显示的是模拟内容，没有真正显示原文对应的片段。用户需要一个能够显示真实原文内容的智能悬浮卡片，提供更好的阅读体验和引用查看功能。

## 需求

### 需求1 - 真实原文片段显示

**用户故事:** 作为用户，当我悬停在引用数字(ref)上时，我希望看到一个卡片显示该引用对应的真实原文片段，而不是模拟内容。

#### 验收标准

1. When 用户悬停在引用数字上时，系统应当显示包含真实原文内容的悬浮卡片
2. When 引用数据可用时，系统应当从ReferenceManager获取真实的段落内容
3. When API不可用时，系统应当优雅降级到模拟数据显示
4. When 引用内容过长时，系统应当截断并显示省略号

### 需求2 - 优化卡片交互体验

**用户故事:** 作为用户，我希望悬浮卡片有流畅的交互体验，包括延迟显示、位置自适应和优雅的动画效果。

#### 验收标准

1. When 用户悬停500ms后，系统应当显示悬浮卡片
2. When 卡片超出视口边界时，系统应当自动调整显示位置(上/下/左/右)
3. When 用户移开鼠标时，系统应当在100ms后隐藏卡片
4. When 卡片显示/隐藏时，系统应当提供平滑的透明度和缩放动画

### 需求3 - 增强卡片信息展示

**用户故事:** 作为用户，我希望悬浮卡片不仅显示原文内容，还能显示相关的元信息，如章节标题、段落位置等。

#### 验收标准

1. When 段落有章节标题时，系统应当在卡片中显示章节信息
2. When 引用为范围(如1-3)时，系统应当显示包含的段落数量
3. When 段落有位置信息时，系统应当显示在原文中的位置
4. When 点击跳转按钮时，系统应当正确跳转到原文位置

### 需求4 - 智能引用跳转导航

**用户故事:** 作为用户，当我点击引用数字时，我希望能够跳转到原文reader界面中对应的段落位置，并且该段落应该被高亮显示。

#### 验收标准

1. When 用户点击引用数字时，系统应当跳转到reader界面对应的原文段落
2. When 目标段落不在当前视口时，系统应当自动滚动到该段落并居中显示
3. When 跳转到目标段落时，系统应当高亮显示该段落3-5秒钟
4. When 在不同的渲染模式(chunks/markdown)下，系统应当正确定位对应的段落
5. When 跳转失败时，系统应当显示友好的错误提示并提供回退方案

### 需求5 - 性能优化和错误处理

**用户故事:** 作为用户，我希望悬浮卡片功能稳定可靠，即使在网络状况不佳或数据异常时也能正常工作。

#### 验收标准

1. When 获取引用内容失败时，系统应当显示友好的错误信息
2. When 引用ID无效时，系统应当显示"引用未找到"提示
3. When 数据加载中时，系统应当显示加载状态指示器
4. When 频繁悬停时，系统应当正确处理防抖逻辑避免重复请求

### 需求6 - 多种引用格式支持

**用户故事:** 作为用户，我希望悬浮卡片能够正确处理各种引用格式，包括单个引用、引用范围和多个引用。

#### 验收标准

1. When 引用为单个数字(如"5")时，系统应当显示第5段的内容
2. When 引用为范围(如"1-3")时，系统应当显示范围内所有段落的摘要
3. When 引用为多个数字(如"1,3,5")时，系统应当显示首个引用的内容并标注总数
4. When 引用格式异常时，系统应当优雅处理并显示解析错误提示
